## P7.2 Security review: targeted pass, fixes on branch `chore/release-hygiene`

Checked: SQL, deep links and intents, URL opening, notifications, logging, key storage, WebView/eval, manifest permissions, secrets.

| Finding | Severity | Status |
|---|---|---|
| SQL is parameterized everywhere; dynamic parts are constants (`col` is a 3-value union) | none | ok |
| RevenueCat API key override read from AsyncStorage in release builds (could point the SDK at another project, e.g. the Test Store, which sells a free `lifetime` product on the entitlement) | medium (needs local write access to app storage) | **fixed**: read only when `__DEV__` |
| Experiment screens (`/selfie`, `/people`, `/today-tags`) reachable by `picdump://` link in release | low | **fixed**: redirect to Discover when not `__DEV__` |
| Search text logged with `console.log` in release | low | **fixed**: `__DEV__` only |
| Pro status is decided on the client (no server) | accepted in ADR 0001/0004 | known |
| `android:allowBackup="true"`: device backup can copy the photo index, face data and profile to the user's Google account | medium | **decision needed**: set to false or exclude the databases with `dataExtractionRules` |
| Keystore passwords were committed in the past (`RELEASE_SIGNING.md`, three commits flagged by `af check`) | medium | **needs the keystore**: treat the passwords as burned; rotate when the upload key is found or reset |
| RevenueCat `test_` Test Store key was in the source and git history | low | removed from source; archive the Test Store app in RevenueCat |
| `RECORD_AUDIO` pulled in by a dependency, unused | low | **fixed**: blocked in `app.json` |
| Notifications carry a route in `data.url`, only app-scheduled local notifications | none | ok |

Gate stays open until the branch is merged and the two decisions (backup, Test Store) are made.

## P4.5 Accessibility baseline: partly passes

Muted text on the screen background is 4.70. Proposed fix: darken Cashmere `inkMuted` to about `#6F625A`. Not applied: tokens belong to P4.2 and the brand colors are changing.
- Dynamic type: nothing disables font scaling (no `allowFontScaling={false}`), so text scales; clipping of fixed-height rows at large sizes has not been checked on a device.
- Gate stays open (contrast fix and a large-text pass on a device).
